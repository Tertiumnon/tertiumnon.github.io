# Development and deployment

## Quick start

```bash
bun install
bun run start    # http://localhost:4200
```

`bun install` also points git at `.githooks/` (the `prepare` script).

## Scripts

| Script | What it does |
| --- | --- |
| `start` | Dev server |
| `build` | Angular build into `dist/` |
| `gh:pages:build` | Production build into `dist/gh-pages/` with `.nojekyll`, as GitHub Pages serves it |
| `test`, `test:ui`, `test:coverage` | Vitest: watch mode, UI, coverage |
| `typecheck` | `tsc --noEmit` |
| `lint:fix` | Format and fix `src/` |
| `generate` | Rebuild all generated data (see below) |
| `project:github:create [repo]` | Rebuild project data; with a repository name, only that project |
| `post:create`, `post:list:create` | Create a post; rebuild the post list |
| `release:patch`, `release:minor`, `release:major` | Version bump, changelog and tag |

`dist/` is build output and is git-ignored.

## Generated data

Projects, project dates, the changelog, posts and Bluesky lines in `src/assets` are generated by `bun run generate`. It reads GitHub through the `gh` CLI, so sign in with `gh auth login` first. A project is listed when its `project.yml` has `https://tertiumnon.github.io` under `publish_on`.

The data is built locally and committed with the code:

- **pre-commit** runs `typecheck`.
- **pre-push** runs `generate` and stops the push when the data changed. Commit the data, then push again.
- **post-merge** on `main` and `develop` runs `generate` and commits the result.

`.github/workflows/refresh-generated.yml` rebuilds the data on GitHub every Monday when it is older than 14 days, or when started by hand with `force`.

## Deployment

Pushing to `main` runs `.github/workflows/deploy-pages.yml`: it builds `dist/gh-pages/` with `gh:pages:build` and publishes it to GitHub Pages. It deploys what is committed and never pushes.

## Zoneless Angular 20

This project is configured to run without Zone.js (zoneless) using `bootstrapApplication`.

- Verify at runtime: the app prints a console message saying whether Zone is present.
- If Zone is detected but you want zoneless behaviour, search for `zone.js` imports and remove them (commonly in `src/polyfills.ts` or 3rd-party libraries). If a dependency requires Zone, either add it to polyfills explicitly or replace the library.
